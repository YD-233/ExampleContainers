## 一、设计（论文）任务与要求

### 1. 设计（论文）任务

本毕业设计要求在 Mythic 框架基础上，设计并实现一个面向实验环境的渗透测试远控系统原型。系统以 Go 语言开发远控植入体（Agent），以 HTTP/HTTPS 为主要通信载体，重点实现任务轮询、命令执行、文件管理、基础代理转发与信息收集等功能。具体任务如下：

1. 需求分析：调研当前常见的 C2 框架与渗透测试工作流，明确系统在任务调度、通信方式、文件操作、代理转发、信息收集等方面的功能需求与非功能需求。
2. 系统架构设计：结合 Mythic 的微服务扩展机制，设计 Payload Type、Agent 与 C2 通信配置的总体技术方案，明确任务下发、结果回传、消息封装与模块边界。
3. Agent 核心功能实现：采用 Go 语言开发跨平台 Agent，完成 Beaconing 心跳轮询、命令执行、文件上传下载、目录浏览、系统状态收集等基础能力。
4. 扩展功能实现：实现简单的 SOCKS5 代理功能，支持基础账号密码认证；实现信息收集模块；实现辅助提权模块，支持调用开源提权辅助工具或执行提权环境探测。
5. 通信与伪装设计：基于 HTTP/HTTPS 协议完成 Agent 与 Mythic 的通信对接，实现基础加密封装、可配置请求路径、User-Agent、Host 及其他请求头的伪装能力，并支持心跳间隔与抖动配置。
6. 测试与结果分析：搭建虚拟测试环境，对系统的功能完整性、跨平台兼容性、通信稳定性和代理转发可用性进行测试，整理测试结果并撰写说明文档。

### 2. 设计（论文）要求

1. 技术规范：代码实现需符合 Go/Python 工程规范，遵循 Mythic 的 Payload Type 与 RPC 接口规范，确保模块划分清晰、结构合理、便于维护。
2. 运行效能：系统应支持稳定的 Beaconing 通信与任务回传，SOCKS5 代理和文件传输功能应能在实验环境中正常运行，具备基础的错误处理与异常恢复能力。
3. 文档质量：毕业论文应围绕系统设计、模块实现、测试过程与结果分析展开，逻辑清晰，表述规范，参考文献符合学校要求。
